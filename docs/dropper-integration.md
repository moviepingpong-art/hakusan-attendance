# イベントドロッパー側の連携

**実装先は別リポジトリ `moviepingpong-art/dropper-app`。** このリポジトリには連携モジュールの原本
[`dropper/attendance-hook.js`](../dropper/attendance-hook.js) と、この記録を置いてある。

---

## いまの形（管理画面を開くだけ）

**ドロッパーは主催者のデータに一切書き込まない。**
カードの **「🙋 出欠システムに保存」** を押すと、読み取り結果を積んだ管理画面
（`attend/admin.html#t=<トークン>`）を新しいタブで開く。**取り込むかどうかは向こうの画面が決める。**

そのため**ドロッパー側に設定が一切ない。** デプロイID・書き込みキー・設定モーダルは撤去ずみ。

```
[ドロッパー] 🙋 出欠システムに保存
   ↓ 押した瞬間に新しいタブを開く → 要項を保存 → 行き先を入れる
[管理画面] 取り込みは自動
          開催日・締切・種目を見せて → [ この内容で出欠を受け付ける ]  ← 1タップ
```

> 以前は設定モーダルにURLと書き込みキーを保存し、ドロッパーから直接イベントを作っていた。
> 端末の設定が消える・PCとスマホで別々に設定が要る、といった問題が続いたので、
> いったん**クリップボードに載せて主催者が貼り付ける**形にし、設定ごと無くした。
> そのうえで、**貼り付けだけを「管理画面を開く」に置き換えた**（設定は戻していない）。
> 貼り付けは、ポップアップを止められたときの逃げ道として残してある。経緯は git 履歴。

### 取り込み先をどう知るか

ドロッパーは**団体IDも合鍵も知らない**。知っているのは管理画面のほうで、
**合鍵をその端末に覚えている**（`localStorage.dropperAdminKey`）ときだけ、開いた先で取り込みまで進む。

覚えていない端末で開いたときは、**取り込まずに `dropperPending` に1時間だけ預かる**。
主催者がご自分の管理リンクを開いた時点で取り込む。**預かりを捨てないのが肝**で、
捨てると「もう一度ドロッパーで読み直す」ことになる。

合鍵を覚えるかどうかは主催者が選ぶ（管理画面の「この端末に覚える／消す」）。
**覚えた端末を使える人は、主催者と同じ操作ができる。** 画面にそう書いてある。
iOS Safari は使わないでいると端末の記憶を捨てるので、**管理リンクの控えは別に残してもらう。**

### 出欠を作るのは1タップ。自動にはしない

**行事（読み取った要項の置き場）と出欠は別物のまま。** カレンダーに入れたいだけの回があるうえ、
読み違えた締切のまま受付が始まると直せない（作り直しになる）。開催日・締切・種目を見せて、
主催者に1回押してもらう。

### ⚠ ホーム画面から起動されたときは、タブを開かない

**ホーム画面に登録したアプリは、ブラウザとは別の入れもの。**
端末の記憶（合鍵）もGoogleのログインも共有しない。そこから `window.open` すると
**ブラウザ側に飛び出す**ので、開いた先の管理画面は「どの団体か分からない」状態になる。
Googleログインもそのたび最初からになる（`accessToken` はもともと保存していない。
ブラウザ側の「Googleに入っている状態」が使い回されていただけ）。

`attendStandalone_()`（`navigator.standalone` と `display-mode`）が true のときは、
**同じ画面で移動する**。そのアプリの中で完結するので、記憶もログインも生きたまま。

**そのアプリに管理リンクを持ち込む道は、貼り付けしかない。**
アドレス欄が無く、LINEやメールのリンクを押すと別のブラウザで開いてしまうため。
管理画面の「すでに団体をお持ちの方」に貼り付け欄を置いてある（`keyFrom` が
`#k=` を拾う。合鍵だけ貼られても通す）。ここを塞ぐと、ホーム画面のアプリでは
**入る手段が無くなる。**

> 「すでにお持ちの方」は**「団体をつくる」より上に、必ず一緒に**出す（`showStart`）。
> つくるほうだけ見せると、持っている人が二つめの団体をつくってしまい、
> 配ったURLは古いほうを指したままになる。

### 帰り道（来かたで2通り）

| 来かた | 帰り方 |
|---|---|
| 別のタブで開かれた（ふつうのブラウザ） | **閉じる。** もとのタブが案内文もカードも抱えたまま残っている |
| 同じ画面で来た（ホーム画面のアプリ） | **前の画面へ戻る。** タブが1枚しかない |

`window.open` で開いたタブでないと `window.close()` は効かないので、閉じるのは
**`window.opener` があるときだけ**。閉じさせてもらえない端末のために、押したあと
「このタブは閉じてかまいません」と出す。

戻るほうは**直前がドロッパーだったときだけ**出す（`document.referrer` を見る）。
`#t=` の有無では決めない。リンクを手で開いた場合、戻り先が別物になるため。

> ブックマークから開いた管理画面には、どちらも出ない。戻る先が無いため。

### アドレス欄に残さないもの

- **`#t=` は読んだらすぐ消す。** 読み直しで二重に取り込まないため
- **記憶から来た合鍵を `#k=` に書き戻さない。** ドロッパーから開いたタブに合鍵を映さないため

> 管理画面を開いたまま管理リンクを開くと、ブラウザは `#` だけ差し替えて**読み直さない**。
> `hashchange` で `reload` させている。これが無いと「開き直したのに何も起きない」になる。

## dropper-app に入れているもの

```
dropper-app/
  attend/                        ← このリポジトリの attend/ をそのままコピー
  calendar/attendance-hook.js    ← dropper/attendance-hook.js をコピー（3言語ぶん）
  calendar/app.js                ← 保存ボタンと案内文
  calendar/i18n.js               ← attend* / annAttend* キーを ja/en/in に追加
  （calendar-en / calendar-in も同じ。app.js と i18n.js はバイト単位で同一）
```

**このリポジトリを直したら dropper-app にも同期すること。** 配信しているのは dropper-app のほう。

## 符号化

`saveToken`（base64url の JSON）と、API側の `importTaikai` が対。
**形を変えるときは両方そろえる。** 試験（`apitest3.js`）では本物の `saveToken` を読み込んで
突き合わせている。片側だけ直しても気づけないため。

トークンに入れているもの：

```
name, date, deadline, place, items[], youkou, detail
```

`detail` は読み取り結果の構造化ずみの項目だけ（OCRの生文は入れない）。
会場の住所は `detail.kaijo_jusho` にあり、API側がそこから拾って
**回答画面の地図ボタン**に使う。

## 要項ファイル

`youkou` はドライブに上げた要項ファイルのリンク。**カレンダーに登録するかどうかとは切り離してある。**

以前はドライブへの保存が「Googleカレンダーに登録」の処理の中にしか無く、
カレンダーを使わない主催者だと回答画面に「要項を見る」が出なかった。
いまは「🙋 出欠システムに保存」を押した時点でも、まだ上げていなければその場で上げる
（`dropper-app` の `attendEnsureYoukou_`）。

- すでに上げてあれば作り直さない（同じファイルが何枚もできる）
- Googleにログインしていなければ何もしない。要項ボタンが出ないだけで、取り込みは進む
- 保存に失敗しても止めない

> ⚠ **タブを開くのも、クリップボードに書くのも、押した瞬間の「ユーザー操作中」でないと通らない。**
> ドライブへの保存を `await` してから `window.open` を呼ぶとポップアップブロックに止められ、
> `writeText` を呼ぶと iOS Safari で**黙って失敗する**。
>
> **先に空のタブを開いておき、文字列ができてから `location.replace` で行き先を入れる。**
> 逃げ道のクリップボードは Promise を渡せる `ClipboardItem` で書く
> （使えない端末は `writeText` → 手でコピー、と落とす）。

## 案内文

**URLを入れない。** 地図・カレンダー・要項は出欠の回答画面にボタンとして出る。
長いURLを2本並べると本文より長くなり、肝心の出欠が埋もれるため。

日本語版の末尾に1行だけ：

```
🙋 下のメニューの「出欠入力」から、出欠を回答してください。
```

リッチメニューに出欠ページを常設しているので、URLは要らない。
**出欠システムに保存していない回だけ**、今までどおり地図とカレンダーのURLを載せる
（その回は回答画面が無いので、外すと行き先が無くなる）。

英語版・インド版は出欠システムに保存する導線が無いので、実質これまでどおり。

## 失敗したとき

作成に失敗したら**ボタンを押せる状態に戻す**。要項を再ドロップさせない
（カレンダーの予定が重複するため）。

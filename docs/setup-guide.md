# セットアップ手順

対象は2種類あります。

- **A. 開発者がやること**（1回だけ）… 配布用テンプレのスプレッドシートを作る
- **B. 主催者がやること**（団体ごと）… テンプレをコピーしてデプロイする

主催者の作業はほぼ**スプレッドシートの中のセットアップ画面**（`gas/setup-ui.html`）で完結します。
`attend/setup.html` は「表をコピーする」ところと「イベントドロッパーに登録する」ところだけを受け持ちます。
この文書はその裏付けです。

---

## A. 配布用テンプレを作る（開発者・1回だけ）

1. 空のスプレッドシートを新規作成する。名前は「出欠テンプレ」など。
2. **拡張機能 → Apps Script** を開く。
3. `コード.gs` の中身を消し、[`gas/attendance-api.gs`](../gas/attendance-api.gs) を丸ごと貼り付けてファイル名を `attendance-api` にする。
4. ファイルを追加して [`gas/tally.gs`](../gas/tally.gs) を貼り付け、`tally` という名前にする。
   - `SS_ID` 等のグローバル定数は **`attendance-api.gs` でだけ宣言している**。`tally.gs` で再宣言すると SyntaxError になる。
5. **ファイル → HTML** で追加し、[`gas/setup-ui.html`](../gas/setup-ui.html) を貼り付けて `setup-ui` という名前にする。
   - 拡張子は付けない（Apps Script が `.html` を足す）。`setupの画面` はこのファイル名で呼び出している。
6. スプレッドシートに戻って再読み込みすると、メニューに **「出欠システム」** が出る。
   **「初期設定（シートを作り直す）」** を実行する（初回は承認画面が出る）。
   → はじめに／設定／名簿／イベント／回答／紐付け／集計 の7シートができ、書き込みキーが自動生成される。
7. 配布前に **「設定」B1・B4 を空にし、名簿・イベント・回答・紐付けの中身も空にしておく**。
   書き込みキーはコピーのたびに引き継がれてしまうので、
   メニュー **「書き込みキーを作り直す」** を主催者に必ず実行してもらうか、B2 を空にして配る。
8. 共有設定を「リンクを知っている全員が閲覧可」にし、URL の末尾 `/edit...` を **`/copy`** に置き換えたものを控える。
9. その URL を [`attend/attend.js`](../attend/attend.js) 冒頭の `TEMPLATE_COPY_URL` に入れる。
   空のままだと `setup.html` のステップ1のボタンが押せない状態（手動手順の案内つき）になる。

## B. 主催者の手順

**主催者にスプレッドシートの列やセルを直接さわらせない。** これが設計の要。
団体名も名簿も、シートの中のセットアップ画面から入れてもらう。

| ステップ | どこで | やること |
|---|---|---|
| 1 | `attend/setup.html` | テンプレを自分のGoogleドライブへ「コピーを作成」 |
| 2 | **表の中** | メニュー「出欠システム → セットアップを開く」 |
| 3 | 〃 | 団体名を入れる |
| 4 | 〃 | **人数を入れる → その人数ぶんの入力欄が出る** → 名前と男女を入れて保存 |
| 5 | 〃 | 図解のとおりデプロイ（ウェブアプリ／実行：**自分**／アクセス：**全員**） |
| 6 | 〃 | URLを貼る（自動取得も試す）→ **匿名で実際に叩いて確認** → 3本のURLと書き込みキーが出る |
| 7 | `attend/setup.html` | URLと書き込みキーを貼って、イベントドロッパーに登録 |

コピー直後の表は「はじめに」シートが開く。そこにメニューの押し方が書いてある
（`onOpen` は承認なしで走る簡易トリガーなので、画面を自動で開くことはできない）。

### セットアップ画面がやってくれる確認

- **同姓同名を弾く。** 出欠は名前で本人を見分けるため、同じ名前が2人いると成立しない
- **「アクセスできるユーザー：自分のみ」を見抜く。** 保存の前に、サーバー側から
  ログインしていない人として `?action=ping` を叩く。ログインHTMLが返ってきたら保存しない
- **`/dev` のURLを採用しない。** 自動取得できても `/exec` で終わらないものは無視する
  （`/dev` は本人しか開けないため、配ると全員がエラーになる）

### つまずきどころ

- **「このアプリは確認されていません」**
  自分で書いたスクリプトを自分で承認するだけ。Google の審査は不要。
  「詳細」→「（プロジェクト名）に移動」→「許可」。
- **アクセスできるユーザーが「自分のみ」になっている**
  参加者が開くと GAS のログイン HTML が返り、ページが「接続できませんでした」と出る。ここが最頻出の事故。
  セットアップ画面のステップ4で弾いているが、**あとで再デプロイするときに戻してしまう**ことがある。
- **★再デプロイの鉄則**
  デプロイ → **デプロイを管理** → 鉛筆 → バージョン「**新しいバージョン**」→ デプロイ。
  **URLは変わらない。**「新しいデプロイ」を連発すると「アクティブなデプロイ無し」状態になって詰まる（旧システムで事故あり）。

## シートの構造

### 設定
| セル | 内容 |
|---|---|
| B1 | 団体名（出欠ページのヘッダに出る） |
| B2 | 書き込みキー（32文字。`createEvent` にだけ必要） |
| B3 | タイムゾーン（既定 `Asia/Tokyo`） |
| B4 | デプロイID（セットアップ画面が自動で入れる。手で書き換えない） |

### 名簿（唯一の必須入力）
| A | B | C |
|---|---|---|
| 名前 | 性別（男／女） | 備考（「退会」と書くと選択肢から消える） |

- 突き合わせは NFKC 正規化＋空白除去で行うので、「山田 太郎」「山田太郎」「山田　太郎」はすべて同じ人として扱われる。
- 性別は `男/男性/M`・`女/女性/F` を吸収する。空欄なら集計の「性別未登録」に入る。

### イベント
| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| イベントID | イベント名 | 開催日 | 申込締切 | 種目（「、」区切り） | 要項リンク | 登録日時 |

- ID は GAS が採番（`ev` + 現在時刻の base36 = 10文字）。手で書く必要はない。
- **申込締切の当日23:59:59をすぎると受付終了。** 締切が空欄なら開催日を締切とみなす。両方空なら締切なし。
- 手で1行足しても動く（IDだけ他と重複しない適当な文字列を入れる）。

### 回答
| A | B | C | D | E |
|---|---|---|---|---|
| タイムスタンプ | 端末ID | 名前 | イベントID | 回答JSON |

- **上書きせず追記し、集計は同じ人の最新行を採用する**（latest-row-wins）。履歴が残るので事故調査ができる。

### 紐付け
| A | B | C | D |
|---|---|---|---|
| 端末ID | 名前 | 性別 | 登録日時 |

- 端末IDはブラウザが `crypto.randomUUID()` で作って localStorage に持つ値。
- 同じ人が別の端末から開くと行が増えるが、集計は名前で行うので実害はない。

### 集計
メニュー「出欠システム → 集計を更新」（`shukei()`）の出力先。
イベント×種目ごとに 〇△× を男女別6列、回答者数、**未回答者の名前**。
未回答者名を出すのはこのシートだけ。参加者に見える画面には人数しか出さない。

## API 一覧

デプロイURL … `https://script.google.com/macros/s/{デプロイID}/exec`

### GET
| action | パラメータ | 返すもの |
|---|---|---|
| （既定） | `d`（任意） | 締切前のイベント一覧＋団体名＋自分の回答 |
| `event` | `e`, `d`（任意） | イベント1件（締切後も返す） |
| `members` | — | 名簿（退会者を除く） |
| `whoami` | `d` | 紐付け済みなら名前・性別 |
| `summary` | `e`（任意） | 種目別〇△×の男女別**人数のみ**。`e` 省略で全イベント |
| `myanswers` | `d` | 締切前の各イベントへのその端末の最新回答 |
| `ping` | — | `{ok:true, org, version}`（疎通確認用） |

### POST（`Content-Type: text/plain` に JSON 文字列）
| action | 送るもの | 動作 |
|---|---|---|
| `register` | `deviceId`, `name` | 名簿にある名前か検証して「紐付け」に追記 |
| `answer` | `deviceId`, `eventId`, `answers` | 「回答」に追記し、その場の集計を返す |
| `createEvent` | `key`, `name`, `date`, `deadline`, `items`, `youkou` | **キー一致時のみ**イベント追記。採番したIDを返す |
| `checkKey` | `key` | キーが合っているかだけ返す（セットアップ用） |

`application/json` で送るとCORSプリフライトが飛んでGASが応えられない。**必ず `text/plain`。**

### セキュリティの考え方
- 読み取りと回答の書き込みは誰でも可。**URLを知っている人＝案内を受け取った人**という前提（旧システムと同じ緩さ）。
- `createEvent` だけ書き込みキー必須。これがないと第三者に勝手なイベントを流し込まれる。
- 書き込みキーは主催者のブラウザの localStorage にだけ置く。参加者向けURLには一切含まれない。
- デプロイIDは露出しても、キーがなければイベントを作れない設計。

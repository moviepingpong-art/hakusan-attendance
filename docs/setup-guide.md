# セットアップ手順

対象は2種類あります。

- **A. 開発者がやること**（1回だけ）… 配布用テンプレのスプレッドシートを作る
- **B. 主催者がやること**（団体ごと）… テンプレをコピーしてデプロイする

主催者の作業はほぼ**スプレッドシートの中のセットアップ画面**（`gas/setup-ui.html`）で完結します。
`attend/setup.html` は「表をコピーする」ところと「イベントドロッパーに登録する」ところだけを受け持ちます。
この文書はその裏付けです。

---

## A. 配布用テンプレを作る（開発者・1回だけ）

1. 空のスプレッドシートを新規作成する。名前は「出欠テンプレ」など。
2. **拡張機能 → Apps Script** を開く。
3. `コード.gs` の中身を消し、[`gas/attendance-api.gs`](../gas/attendance-api.gs) を丸ごと貼り付けてファイル名を `attendance-api` にする。
4. ファイルを追加して [`gas/tally.gs`](../gas/tally.gs) を貼り付け、`tally` という名前にする。
   - `SS_ID` 等のグローバル定数は **`attendance-api.gs` でだけ宣言している**。`tally.gs` で再宣言すると SyntaxError になる。
5. **ファイル → HTML** で追加し、[`gas/setup-ui.html`](../gas/setup-ui.html) を貼り付ける。
   名前の入力欄には **`setup-ui` とだけ入れる**。`.html` は Apps Script が自動で付けるので、
   ファイル一覧には `setup-ui.html` と表示される。
   - **HTMLだけは名前が一致していないと動かない。** `セットアップを開く()` が
     `HtmlService.createHtmlOutputFromFile('setup-ui')` と名前で呼び出しているため。
   - 逆に **`.gs` のファイル名は実行に関係ない**（すべて1つの領域にまとめて読み込まれるため、
     綴りが違っても動いてしまう）。だからこそ後で迷わないよう、この文書と同じ名前に揃えておく。
6. **マニフェストを差し替える**（デプロイ画面のプルダウンを先に埋めておくため。下記「マニフェスト」参照）。
   - 左の歯車 **プロジェクトの設定** → **「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック**
   - エディタに出た `appsscript.json` の中身を [`gas/appsscript.json`](../gas/appsscript.json) で置き換える
7. スプレッドシートに戻って再読み込みすると、メニューに **「出欠システム」** が出る。
   **「初期設定（シートを作り直す）」** を実行する（初回は承認画面が出る）。
   → はじめに／設定／名簿／イベント／回答／紐付け／集計 の7シートができ、書き込みキーが自動生成される。
8. 配布前に **「設定」B1 を空にし、名簿・イベント・回答・紐付けの中身も空にしておく**。
   - **書き込みキー（B2）とデプロイID（B4）は気にしなくてよい。** コピーされた表は初回に
     自動で判定して、キーを作り直し、デプロイIDを捨てる（下記「コピーの検知」）。
   - 動作確認のためにテンプレ自体でデプロイを試しても、そのデプロイIDがコピー先へ漏れることはない。
9. 共有設定を「リンクを知っている全員が閲覧可」にし、URL の末尾 `/edit...` を **`/copy`** に置き換えたものを控える。
10. その URL を [`attend/attend.js`](../attend/attend.js) 冒頭の `TEMPLATE_COPY_URL` に入れる。
   空のままだと `setup.html` のステップ1のボタンが押せない状態（手動手順の案内つき）になる。

### マニフェスト（`appsscript.json`）

```json
{
  "timeZone": "Asia/Tokyo",
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
}
```

**`webapp` を書いておく理由。** デプロイのダイアログがこの値を初期値として開くので、
**「実行するユーザー：自分」「アクセスできるユーザー：全員」を選ぶ操作そのものが要らなくなる**。
「全員」の選び忘れは最頻出の事故なので、選択肢として残さないのがいちばん確実。

**2026-08-13 に実機で確認ずみ。** 期待以上に効いていて、

- 「種類の選択」が最初から **ウェブアプリ**（⚙ から選ぶ操作も要らない）
- 「次のユーザーとして実行」＝**自分**
- 「アクセスできるユーザー」＝**全員**

主催者の操作は「デプロイ → 新しいデプロイ → **デプロイ**」の3クリックで済む。
それでも念のため、セットアップ画面のステップ4で匿名アクセスを実測して確かめている。

### コピーの検知（`resetIfCopied_`）

「設定」B5 に自分のファイルIDを控えてある。表をコピーすると**中身だけが引き継がれてファイルIDは変わる**ので、
食い違っていれば「コピーされた直後」と判断できる。セットアップ画面を開いたときに1度だけ走り、
**引き継いではいけない2つ**を捨てる。

| 値 | 引き継ぐと何が起きるか |
|---|---|
| 書き込みキー（B2） | 全団体で同じキーになる。他団体のキーを知っている人が、別団体のイベントを作れてしまう |
| デプロイID（B4） | セットアップ画面が「完成」から始まり、**コピー元のデプロイを指したURL**を配ってしまう |

団体名と名簿はそのまま残す（自分の表を複製して別の団体を作る使い方を壊さないため）。

**`oauthScopes` は意図的に書いていない。** 書かないと Apps Script がコードから自動判定する。
手で並べると、書き漏らした権限だけが実行時に落ちる（`UrlFetchApp` を使う疎通確認など）。
自動判定に任せるほうが安全。

## B. 主催者の手順

**主催者にスプレッドシートの列やセルを直接さわらせない。** これが設計の要。
団体名も名簿も、シートの中のセットアップ画面から入れてもらう。

| ステップ | どこで | やること |
|---|---|---|
| 1 | `attend/setup.html` | テンプレを自分のGoogleドライブへ「コピーを作成」 |
| 2 | **表の中** | メニュー「出欠システム → セットアップを開く」 |
| 3 | 〃 | 団体名を入れる |
| 4 | 〃 | **人数を入れる → その人数ぶんの入力欄が出る** → 名前と男女を入れて保存 |
| 5 | 〃 | 図解のとおりデプロイ（ウェブアプリ／実行：**自分**／アクセス：**全員**） |
| 6 | 〃 | URLを貼る → **匿名で実際に叩いて確認** → 3本のURLと書き込みキーが出る |
| 7 | `attend/setup.html` | URLと書き込みキーを貼って、イベントドロッパーに登録 |

コピー直後の表は「はじめに」シートが開く。そこにメニューの押し方が書いてある
（`onOpen` は承認なしで走る簡易トリガーなので、画面を自動で開くことはできない）。

### セットアップ画面がやってくれる確認

- **同姓同名を弾く。** 出欠は名前で本人を見分けるため、同じ名前が2人いると成立しない
- **「アクセスできるユーザー：自分のみ」を見抜く。** 保存の前に、サーバー側から
  ログインしていない人として `?action=ping` を叩く。ログインHTMLが返ってきたら保存しない
- **`/dev` のURLを採用しない。** 貼り付けられたURLが `/exec` で終わらないものは無視する
  （`/dev` は本人しか開けないため、配ると全員がエラーになる）

### つまずきどころ

- **「このアプリは確認されていません」**
  自分で書いたスクリプトを自分で承認するだけ。Google の審査は不要。
  「詳細」→「（プロジェクト名）に移動」→「許可」。
- **アクセスできるユーザーが「自分のみ」になっている**
  参加者が開くと GAS のログイン HTML が返り、ページが「接続できませんでした」と出る。ここが最頻出の事故。
  セットアップ画面のステップ4で弾いているが、**あとで再デプロイするときに戻してしまう**ことがある。
- **★再デプロイの鉄則**
  デプロイ → **デプロイを管理** → 鉛筆 → バージョン「**新しいバージョン**」→ デプロイ。
  **URLは変わらない。**「新しいデプロイ」を連発すると「アクティブなデプロイ無し」状態になって詰まる（旧システムで事故あり）。

### 「CORSでブロックされました」と出たら、まず404を疑う

ブラウザのコンソールに次のように出ることがある。

```
Access to fetch at 'https://script.google.com/macros/s/…/exec' from origin
'https://app.dropper-tools.com' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

**これはCORSの設定ミスではない。** デプロイIDが存在しないときGASは404ページを返し、
そのページにCORSヘッダーが付かないため、ブラウザがCORSエラーとして報告しているだけ。
コンソールをよく見ると、同じ場所に `404 (Not Found)` が並んで出ている。

切り分けは、`…/exec?action=ping` を**ブラウザのアドレスバーで直接開く**のが速い。

| 直接開いた結果 | 意味 |
|---|---|
| `{"ok":true,"org":"…","version":"v1.1"}` | デプロイは正常。原因は別（呼び出し側のURLの綴りなど） |
| Googleドライブ「リクエストされたファイルは存在しません。」 | **そのデプロイIDは存在しない** |
| Googleのログイン画面 | アクセスできるユーザーが「全員」になっていない |

**存在しないと出たときは、URLを手で書き写していないかを最初に疑うこと。**
デプロイIDは72字で `I`（大文字のアイ）と `l`（小文字のエル）、`0` と `O` が紛らわしく、
1文字違うだけで404になる。2026-08-16 に実際にこれで半日溶かした。
**必ず「デプロイを管理」の「コピー」ボタンか、セットアップ画面が出した3本のURLをそのまま使う。**
目で読んで打ち直さない。

### 設定が保存できない端末がある

iOS Safari の **「サイト超えトラッキングを防ぐ」** やプライベートブラウズ、Cookieのブロック下では
`localStorage` が使えず、主催者の設定（デプロイID・書き込みキー）が保存されないことがある。

- 保存の可否は `lsSet` が**書いたあと読み直して**判定し、`saveSettings` が `stored` で返す
  （例外を投げずに黙って捨てる実装があるため、`try/catch` だけでは足りない）
- **保存できなくても作業は続けられる。** `attendance-hook.js` は控え（`mem`）を持っていて、
  そのページを開いているあいだは設定が効く。だから**ブラウザ設定の変更は要らない**。
  開き直すと消えるので、そのときは貼り直してもらう。モーダルはその旨を警告色で出す
  - `lsSet` を `&&` で繋がないこと。左が false のとき右が呼ばれず、控えにも入らない
- **参加者側は影響を受けない。** 端末IDが消えても名簿から名前を選び直せば復旧する。
  回答は端末IDではなく**名前**に紐づけて保存しているので、過去の回答も失われない

## シートの構造

### 設定
| セル | 内容 |
|---|---|
| B1 | 団体名（出欠ページのヘッダに出る） |
| B2 | 書き込みキー（32文字。`createEvent` にだけ必要） |
| B3 | タイムゾーン（既定 `Asia/Tokyo`） |
| B4 | デプロイID（セットアップ画面が自動で入れる。手で書き換えない） |
| B5 | ファイルID（コピーの検知に使う控え。手で書き換えない） |

### 名簿（唯一の必須入力）
| A | B | C |
|---|---|---|
| 名前 | 性別（男／女） | 備考（「退会」と書くと選択肢から消える） |

- 突き合わせは NFKC 正規化＋空白除去で行うので、「山田 太郎」「山田太郎」「山田　太郎」はすべて同じ人として扱われる。
- 性別は `男/男性/M`・`女/女性/F` を吸収する。空欄なら集計の「性別未登録」に入る。

### イベント
| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| イベントID | イベント名 | 開催日 | 申込締切 | 種目（「、」区切り） | 要項リンク | 登録日時 |

- ID は GAS が採番（`ev` + 現在時刻の base36 = 10文字）。手で書く必要はない。
- **申込締切の当日23:59:59をすぎると受付終了。** 締切が空欄なら開催日を締切とみなす。両方空なら締切なし。
- 手で1行足しても動く（IDだけ他と重複しない適当な文字列を入れる）。

### 回答
| A | B | C | D | E |
|---|---|---|---|---|
| タイムスタンプ | 端末ID | 名前 | イベントID | 回答JSON |

- **上書きせず追記し、集計は同じ人の最新行を採用する**（latest-row-wins）。履歴が残るので事故調査ができる。

### 紐付け
| A | B | C | D |
|---|---|---|---|
| 端末ID | 名前 | 性別 | 登録日時 |

- 端末IDはブラウザが `crypto.randomUUID()` で作って localStorage に持つ値。
- 同じ人が別の端末から開くと行が増えるが、集計は名前で行うので実害はない。

### 集計
メニュー「出欠システム → 集計を更新」（`shukei()`）の出力先。
イベント×種目ごとに 〇△× を男女別6列、回答者数、**未回答者の名前**。
未回答者名を出すのはこのシートだけ。参加者に見える画面には人数しか出さない。

## API 一覧

デプロイURL … `https://script.google.com/macros/s/{デプロイID}/exec`

### GET
| action | パラメータ | 返すもの |
|---|---|---|
| （既定） | `d`（任意） | 締切前のイベント一覧＋団体名＋自分の回答 |
| `event` | `e`, `d`（任意） | イベント1件（締切後も返す） |
| `members` | — | 名簿（退会者を除く） |
| `whoami` | `d` | 紐付け済みなら名前・性別 |
| `summary` | `e`（任意） | 種目別〇△×の男女別**人数のみ**。`e` 省略で全イベント |
| `myanswers` | `d` | 締切前の各イベントへのその端末の最新回答 |
| `ping` | — | `{ok:true, org, version}`（疎通確認用） |

### POST（`Content-Type: text/plain` に JSON 文字列）
| action | 送るもの | 動作 |
|---|---|---|
| `register` | `deviceId`, `name` | 名簿にある名前か検証して「紐付け」に追記 |
| `answer` | `deviceId`, `eventId`, `answers` | 「回答」に追記し、その場の集計を返す |
| `createEvent` | `key`, `name`, `date`, `deadline`, `items`, `youkou` | **キー一致時のみ**イベント追記。採番したIDを返す |
| `checkKey` | `key` | キーが合っているかだけ返す（セットアップ用） |

`application/json` で送るとCORSプリフライトが飛んでGASが応えられない。**必ず `text/plain`。**

### セキュリティの考え方
- 読み取りと回答の書き込みは誰でも可。**URLを知っている人＝案内を受け取った人**という前提（旧システムと同じ緩さ）。
- `createEvent` だけ書き込みキー必須。これがないと第三者に勝手なイベントを流し込まれる。
- 書き込みキーは主催者のブラウザの localStorage にだけ置く。参加者向けURLには一切含まれない。
- デプロイIDは露出しても、キーがなければイベントを作れない設計。
